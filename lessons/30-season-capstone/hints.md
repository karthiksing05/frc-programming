# Hints — Lesson 30

## Hint 1 — Where to start

Write the strategy document before any code. One page: what this robot does, what it does not, and how it scores. Everything downstream is easier when that exists.

## Hint 2 — The shape of the answer

Then build in dependency order — drivetrain, mechanisms one at a time, superstructure, autos — and finish each before starting the next.

## Hint 3 — What usually goes wrong

Starting five mechanisms and finishing none. This is the single most common way a capstone dies.

Saving testing for the end. Tests written after the fact test what the code does, not what it should do.

Scope that grows every time something works. The strategy document exists to be re-read.
